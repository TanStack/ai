You run TanStack AI 0.x and you want 1.0. Good news: 1.0 has no new concepts to learn. It removes the APIs that 0.x marked as deprecated. Every replacement already shipped in 0.x, so you can make most of these changes before you upgrade.

1. Update every `@tanstack/ai*` package to `1.0` in one go. A 1.0 client needs a 1.0 server.
2. If you use `@tanstack/ai-react-ui`, `@tanstack/ai-solid-ui`, or `@tanstack/ai-vue-ui`, remove it. These packages have no 1.0 release.
3. Run the codemod below.
4. Run your type checker. Fix each error with the tables on this page.
5. If you keep data from 0.x (chats, runs, files), read [Saved data](#saved-data) before you deploy.

## Run the codemod

The codemod does the most common renames for you: `body` to `forwardedProps`, Svelte `updateBody` to `updateForwardedProps`, and `chat({ conversationId })` to `chat({ threadId })`.

```bash
npx jscodeshift \
  --parser=tsx \
  -t https://raw.githubusercontent.com/TanStack/ai/main/codemods/ag-ui-compliance/transform.ts \
  "src/**/*.{ts,tsx}"
```

Add `--dry --print` to see the changes first. The codemod does not change server code that reads `body.data`. The [server section](#on-the-server) shows that fix.

## In the browser

This section is for code that uses `useChat`, `ChatClient`, a chat UI factory, or any other client package.

### `body` is now `forwardedProps`

The chat-level `body` option is gone from `ChatClient`, `updateOptions`, every chat hook, `createChatHook` and `useAppChat` overrides, and Angular `injectChat`. Use `forwardedProps`:

```diff
  useChat({
    connection: fetchServerSentEvents('/api/chat'),
-   body: { provider: 'openai' },
+   forwardedProps: { provider: 'openai' },
  })
```

On Svelte, `updateBody` is now `updateForwardedProps`.

These keep `body`, because it is a different option:

- The connection adapter option, for example `fetchServerSentEvents(url, { body })`.
- The per-call option, `sendMessage(content, { body })`.
- The generation hooks, for example `useGenerateImage({ body })` and its `updateBody`.

### Interrupts

Read `interrupts`, and resolve each item with its own methods:

```diff
- const { pendingInterrupts, resumeInterrupts } = useChat(chatOptions)
+ const { interrupts } = useChat(chatOptions)

- const approval = pendingInterrupts.find((item) => item.kind === 'tool-approval')
- await resumeInterrupts(resumeItems)
+ const approval = interrupts.find((item) => item.kind === 'tool-approval')
+ if (approval?.kind === 'tool-approval') approval.resolveInterrupt(true)

- interrupt.error?.message
+ interrupt.errors[0]?.message
```

| Removed | Use instead |
| --- | --- |
| `pendingInterrupts` | `interrupts` |
| `ChatClient.getPendingInterrupts()` | `ChatClient.getInterrupts()` |
| `resumeInterrupts(items)` | `interrupt.resolveInterrupt(...)`, `interrupt.cancel()`, or `resolveInterrupts(...)`. For raw recovery tools, `resumeInterruptsUnsafe(items)`. |
| `interrupt.error` | `interrupt.errors[0]` |
| `addToolApprovalResponse()` (all frameworks and `ChatClient`) | `resolveInterrupt` on the bound `tool-approval` interrupt |

An interrupt from a 0.x server that has no binding now shows as `kind: 'unbound'`. You cannot resume it. The error codes `legacy-unsupported` and `legacy-submit-failed` are gone. See [Tool Approval](../interrupts/tool-approval) for a full approval screen.

### Chat UI components

The ready-made components `Chat`, `ChatMessages`, `ChatMessage`, `ChatInput`, `ToolApproval`, and the old `useChatContext` export are gone from `@tanstack/ai-react/ui`, `@tanstack/ai-solid/ui`, `@tanstack/ai-vue/ui`, and `@tanstack/ai-remix/ui`. Their prop types are gone too. Build the UI with `createChatHook`. You supply each component, and the factory types them from your chat options:

```diff
- import { Chat, ChatMessages, ChatInput } from '@tanstack/ai-react-ui'
+ import { createChatHook } from '@tanstack/ai-react/ui'

+ const { useAppChat } = createChatHook({
+   options: chatOptions,
+   components: {
+     layout: ({ Messages, Input }) => (
+       <main>
+         <Messages />
+         <Input />
+       </main>
+     ),
+     message: ({ message, Parts }) => <article data-role={message.role}><Parts /></article>,
+     input: ChatForm,
+   },
+   partsComponents: { text: ({ part }) => <p>{part.content}</p>, fallback: () => null },
+ })

  export function ChatScreen() {
-   return (
-     <Chat connection={connection}>
-       <ChatMessages />
-       <ChatInput />
-     </Chat>
-   )
+   const chat = useAppChat()
+   return <chat.AppChat />
  }
```

`TextPart` and `ThinkingPart` stay. Import them from the same `/ui` subpath. For a complete, runnable version, start with [A chat box with no tools](../ui/recipes/basic-chat). Then open the guide for your framework: [React](../ui/react), [Solid](../ui/solid), [Vue](../ui/vue), or [Remix](../ui/remix).

If you build your own framework adapter, use `createChatUI`. See [Custom adapters](../ui/custom-adapters).

### Other client renames

| Removed | Use instead |
| --- | --- |
| `RealtimeAdapter`, `RealtimeConnection` from `@tanstack/ai-client` | Import them from `@tanstack/ai` |
| `useWebMCPTools` (React, Preact, Solid, Vue, Octane) | `useRegisterWebMCPTools` |
| `injectWebMCPTools` (Angular) | `injectRegisterWebMCPTools` |
| `createWebMCPTools` (Svelte, Remix) | `createRegisterWebMCPTools` |
| Client persistence `getItem` that returns `UIMessage[]` | Return `{ messages }` (see [Saved data](#saved-data)) |

Each WebMCP options type follows its function, for example `UseWebMCPToolsOptions` is now `UseRegisterWebMCPToolsOptions`.

## On the server

This section is for your chat endpoint, middleware, custom adapters, and any server that is not TanStack AI but talks to a TanStack AI client.

### `conversationId` is now `threadId`

```diff
  const params = await chatParamsFromRequest(request)
  const stream = chat({
    adapter: openaiText('gpt-6.1-sol'),
    messages: params.messages,
-   conversationId: params.forwardedProps.conversationId,
+   threadId: params.threadId,
  })
```

Middleware reads `ctx.threadId`. `ctx.conversationId` is gone.

### Read `forwardedProps`, not `data`

The client sends the extra fields only as `forwardedProps`. The `data` copy is gone.

```diff
  const params = await chatParamsFromRequest(request)
- const provider = params.forwardedProps.provider ?? body.data?.provider
+ const provider = params.forwardedProps.provider
```

`chatParamsFromRequestBody(body).context` is now `aguiContext`.

### Custom servers that stream to a TanStack AI client

If your server does not use `chat()` and `toServerSentEventsResponse()`, check these points:

- **Stop sending `data: [DONE]`.** End the run with a `RUN_FINISHED` event. The client cannot parse a `[DONE]` line and reports an error.
- **Set `message` on `RUN_ERROR`.** The client reads only the top-level `message` and `code`. It ignores a nested `error.message`.
- **Send thinking as `REASONING_*` events.** The client does not read `STEP_STARTED` or `STEP_FINISHED` for thinking text.
- **Send approvals and client tools as interrupts.** End the run with `RUN_FINISHED` and an interrupt outcome. The CUSTOM events `approval-requested` and `tool-input-available` are not read. See [Interrupts](../interrupts/overview).

TanStack AI adapters also no longer send `STEP_STARTED` or `STEP_FINISHED` for reasoning. If your middleware or devtools read those events for thinking, read `REASONING_*` events.

### Video adapters

`getVideo()` is now required, and `getVideoUrl()` is gone from `VideoAdapter` and `BaseVideoAdapter`:

```diff
  class MyVideoAdapter extends BaseVideoAdapter {
-   async getVideoUrl(jobId: string) {
+   async getVideo(jobId: string) {
      return { jobId, url: await this.fetchUrl(jobId) }
    }
  }
```

In app code, call `getVideoJobStatus({ adapter, jobId })` instead of `adapter.getVideoUrl(jobId)`. See [Video Generation](../media/video-generation).

### Usage numbers

`TokenUsage.durationSeconds` and `TokenUsage.unitsBilled` are gone. Read `billed`. It holds the quantity and its unit:

```diff
- const seconds = result.usage?.durationSeconds
+ const billed = result.usage?.billed
+ const seconds = billed?.unit === 'seconds' ? billed.quantity : undefined
```

The OpenTelemetry attributes follow the same change. `tanstack.ai.usage.duration_seconds` and `tanstack.ai.usage.units_billed` are gone. Read `tanstack.ai.usage.billed_quantity` and `tanstack.ai.usage.billed_unit`. See [OpenTelemetry](../advanced/otel).

### Renamed types and helpers

| Removed | Use instead |
| --- | --- |
| `AGUIEventType`, `StreamChunkType` | The `EventType` enum, or `` `${EventType}` `` for the string union |
| `UsageTotals`, `ImageUsage` | `TokenUsage` |
| `OtelSpanKind` | `OtelSpanScope` |
| `StreamProcessor.startAssistantMessage()` | `StreamProcessor.prepareAssistantMessage()` |
| `ApprovalRequestedEvent`, `ToolInputAvailableEvent` | The interrupt outcome on `RUN_FINISHED` |
| `toolName` on `TOOL_CALL_START` chunks | `toolCallName` |

In `@tanstack/ai-event-client`, `CompactionAppliedEvent` and the `'compaction:applied'` event are now `CompactionStateEvent` and `'compaction:state'`.

`prepareAssistantMessage()` returns nothing. The processor makes the assistant message when the first content arrives.

### Provider adapters

Each provider tool type alias is gone. Use the `Config` name, for example `WebSearchTool` is now `WebSearchToolConfig`:

| Package | Removed aliases |
| --- | --- |
| `@tanstack/ai-anthropic` | `BashTool`, `CodeExecutionTool`, `ComputerUseTool`, `CustomTool`, `MemoryTool`, `TextEditorTool`, `WebFetchTool`, `WebSearchTool` |
| `@tanstack/ai-gemini` | `CodeExecutionTool`, `ComputerUseTool`, `FileSearchTool`, `GoogleMapsTool`, `GoogleSearchRetrievalTool`, `GoogleSearchTool`, `UrlContextTool` |
| `@tanstack/ai-openai`, `@tanstack/openai-base` | `ApplyPatchTool`, `CodeInterpreterTool`, `ComputerUseTool`, `CustomTool`, `FileSearchTool`, `FunctionTool`, `ImageGenerationTool`, `LocalShellTool`, `MCPTool`, `ShellTool`, `WebSearchPreviewTool`, `WebSearchTool` |
| `@tanstack/ai-openrouter` | `WebSearchTool` |

Other provider changes:

- **Anthropic skills.** Move `modelOptions.container.skills` to the code execution tool: `codeExecutionTool(config, { skills })`.
- **Anthropic media type.** Delete `mediaType` from image and document metadata. The adapter reads the type from `source.mimeType`. The types `AnthropicImageMediaType` and `AnthropicDocumentMediaType` are gone.
- **Gemini image models.** Google shut down `gemini-3.1-flash-image-preview`, `gemini-3-pro-image-preview`, and `gemini-2.5-flash-image`. Use `gemini-3.1-flash-image`, `gemini-3-pro-image`, or `gemini-3.1-flash-lite-image`. The type `Gemini25FlashImageSize` is gone.
- **Grok voice.** `grok-voice-think-fast-1.0` is now `grok-voice-think-fast-2.0`.

## Saved data

1.0 does not read some formats that 0.x saved. Do these steps before you deploy:

1. **Finish or clear the runs in flight.** `@tanstack/ai-sandbox-cloudflare` no longer reads run-log records in the 0.x layout (`status: 'done' | 'error'` and `createdAt`). `migrateStoredRunRecord` is gone.
2. **Resolve or drop the pending interrupts.** `@tanstack/ai-persistence` resumes only bound interrupts. A record saved before interrupt bindings existed does not resume.
3. **Add `blobKey` to artifact records.** `ArtifactRecord.blobKey` is now required, and a record without it does not load. A 0.x record without `blobKey` used the key `artifacts/<runId>/<artifactId>`. Write that value into those records. A custom store must save `blobKey`. `resolveArtifactBlobKey()` is gone, so read `record.blobKey`.
4. **Return `{ messages }` from client persistence.** `getItem` must return `{ messages, resume? }`. A bare `UIMessage[]` does not load. Wrap old values in `getItem`:

```diff
  getItem: (id) => {
    const saved = JSON.parse(localStorage.getItem(id) ?? 'null')
-   return saved
+   return Array.isArray(saved) ? { messages: saved } : saved
  },
```

In `@tanstack/ai-sandbox`, `FileEvent` is now `SandboxFileEvent`. `SandboxSnapshotBundle.resolveArtifactBlobKey` is gone, because each record has `blobKey`. See [Client Persistence](../persistence/client-persistence) and [Keep generated files](../persistence/keep-generated-files).

## Done

Your type checker passes, your chat streams, and your saved chats load. You are on 1.0.
